# 脱壳机用法（apk_unpack.ps1）

针对 **Apacker（`AKPH`/`AKPC`）** 加壳的 x64 PE 的**纯静态**脱壳工具：不运行样本，不需要调试器。

## 依赖

- Windows PowerShell 5.1 或 PowerShell 7+（只用 `.NET` 自带 `System.Security.Cryptography.Aes`）
- 无需 Python / IDA / Ghidra / 第三方库

## 运行

```powershell
# 方式 A：不落盘执行（绕过执行策略限制，推荐）
$sb = [scriptblock]::Create((Get-Content -Raw -Encoding UTF8 .\apk_unpack.ps1))
& $sb -InputFile "..\样本\Campus_Network_learning.exe" -OutDir "..\产物"

# 方式 B：放开当前进程策略后直接调用
Set-ExecutionPolicy -Scope Process Bypass -Force
.\apk_unpack.ps1 -InputFile "..\样本\Campus_Network_learning.exe" -OutDir "..\产物"
```

## 参数

| 参数 | 必填 | 说明 |
|---|---|---|
| `-InputFile` | 是 | 被 Apacker 加壳的 exe 路径 |
| `-OutDir` | 是 | 输出目录（不存在会自动创建） |

## 输出

| 文件 | 内容 |
|---|---|
| `<名字>.unpacked.exe` | 加密页全部替换为明文，`AddressOfEntryPoint` 已改回 **原始 OEP** |
| `<名字>.text.bin` | 解密后的 `.text` 原始字节（可直接丢进 IDA/Ghidra 做差异比对） |
| `<名字>.report.json` | 结构报告：密钥、key 值、OEP、页数、算法号、导入数、每页 CRC/Match 记录 |

控制台会打印：

```
[+] stub 节: .AXJvbGt  VA=0x58000  Raw=0x52E00
[+] AKPH: ver=1 stubVA=0x58000 stage2VA=0x63000 encLen=0x1460 payloadLen=0x3460 key=0xC4B81C94
[+] AES-256 key = DFE1C48C...25587FD6
[+] AKPC: OEP=0x11B40 flags=0x7 pages=57 cipher=5 imports=115 tableOff=0xF8 guard=1000ms
[+] 页: 57 条, 已解密 57; ...
```

## 原理（对应参数）

1. **定位桩节**：遍历节表，找节起始 `+0x10` 处等于 `AKPH` 的节。
2. **解析 AKPH**：`+0x18` 桩节 VA、`+0x1C` stage2 VA、`+0x20` 解密长度、`+0x30` key 值。
3. **密钥派生**：`key[i] = ~T1[i] ^ T2[i] ^ (key&0xFF) ^ ((key>>8)&0xFF)`，`T1/T2` 在桩节 `+0x38`/`+0x58`。
4. **解 stage2**：AES-256-CTR，IV = `[key值 4B LE][12 个 0]`；解出后校验 `AKPC` 魔数。
5. **读配置**：`+0x0C` OEP、`+0x24` 页数、`+0x3C` 页表偏移。
6. **逐页解密**：每页 IV = `[key值 4B LE][0][页VA 4B LE][0]`，长度取页表 `+0x06`（0 则按 0x1000）。
7. **回填 OEP** 并写盘。

## 自检结果

见 `自检结果.txt`。要点：

- 样本 1：`.text` 57 页全解，输出与"运行时内存里壳自己解过的页"**逐字节一致（差异 0）**；
- 样本 2：自动识别（`OEP=0x6840`、34 页、88 导入），无需改参数。

## 已知限制

| 限制 | 说明 |
|---|---|
| 仅 `PE32+` (x64) | 壳本身只支持 64 位 |
| 仅 `AKPH`/`AKPC` | 不是 Apacker 的文件会直接报"未找到 AKPH 头" |
| 页大小假定 0x1000 | 与打包器 `section alignment must be 0x1000` 的约束一致 |
| 页表 CRC 字段不参与判定 | 实测与标准反射 CRC32 不符（变体/覆盖范围不同），仅记录供参考 |
| 输出**不能直接运行** | Apacker 清空了导入表，桩才会重建 IAT；脱壳机不重建导入，因此 `.unpacked.exe` 里 IAT 全 0。用于 **静态分析**（IDA/Ghidra 可正常读） |
| 不含导入名单导出 | 导入名需要运行时内存（`中间产物\unpack_work\iat_resolved.json` 是本样本的结果） |

## 想让它"能运行"可以怎么做

见 `..\报告\04_实验记录与结论.md` 的"未解问题"：把 IAT 迁到可写新节，并把 `.text` 内所有引用
`0x3A000~0x3A400` 的 RIP 相对指令重定向过去；或退一步用"保留桩、只关加密"的重打包方案。
